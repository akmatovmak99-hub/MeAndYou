# Правила работы с коммитами

## Перед push проверяй, что коммитишь

Прежде чем пушить изменения, **обязательно посмотри, что реально попадает в коммит**. Это 30 секунд, которые спасают команду от мусора в репозитории.

```bash
git status              # какие файлы изменены/добавлены
git diff --staged       # что именно уходит в коммит
git log --stat -1       # что уже в последнем коммите (если уже закоммитил)
```

## Что НЕЛЬЗЯ коммитить

В коммит должны попадать **только файлы, относящиеся к твоей задаче**. Не коммить:

- `.idea/` — настройки IntelliJ IDEA (у каждого свои)
- `.vscode/` — настройки VS Code
- `.gradle/` — кеш Gradle
- `build/`, `out/`, `target/`, `bin/` — сборочные артефакты
- `.DS_Store` — системный файл macOS
- `Thumbs.db` — системный файл Windows
- `*.iml` — файлы модулей IntelliJ
- `*.log` — локальные логи
- `local.properties`, `.env` — локальные конфиги и секреты
- Любые файлы, которые ты не менял в рамках задачи

Все такие файлы должны быть в `.gitignore`.

## Что делать, если случайно закоммитил лишнее

### Файл ещё НЕ запушен

Если закоммитил `.idea/` (или что-то другое) локально, но ещё не запушил в remote:

```bash
# 1. Убрать файл/папку из git, но оставить на диске
git rm -r --cached .idea/

# 2. Убедиться, что она в .gitignore
echo ".idea/" >> .gitignore

# 3. Пересобрать последний коммит с исправлением
git add .gitignore
git commit --amend --no-edit
```

### Файл УЖЕ запушен в remote

Если лишнее уже уехало на сервер:

```bash
git rm -r --cached .idea/
echo ".idea/" >> .gitignore
git add .gitignore
git commit -m "chore: remove .idea from tracking"
git push
```

Файл останется в истории (в старых коммитах), но перестанет отслеживаться в новых.

## Важно про флаги `git rm`

- `git rm file` — удаляет файл **И из git, И с диска** ⚠️
- `git rm --cached file` — удаляет **только из git**, на диске файл остаётся ✓
- `-r` — рекурсивно, обязательно для папок

**Правило:** для удаления мусора из репозитория всегда используй `git rm --cached`, а не просто `git rm`. Иначе удалишь свои локальные настройки IDE.

## Чек-лист перед push

- [ ] `git status` — только нужные файлы изменены
- [ ] `git diff --staged` — все изменения относятся к задаче
- [ ] Нет `.idea/`, `.gradle/`, `build/`, `.DS_Store` в коммите
- [ ] Сообщение коммита в формате команды (например, `AFFILIATES-XXXXX: описание`)
- [ ] Тесты проходят локально

## Полезные команды для проверки

```bash
# Показать все файлы, которые git отслеживает
git ls-files

# Проверить, игнорируется ли файл
git check-ignore -v path/to/file

# Посмотреть, какие файлы попали в последний коммит
git show --stat HEAD

# Отменить staging файла (если добавил лишнее через git add)
git restore --staged path/to/file
```
